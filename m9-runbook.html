1.1

Install hwloc 2.9.3 from tarball

hwloc is the dependency. likwid links against it at compile time. Install hwloc first, into your personal /apps/software/$USER/ subtree.

Commands
cd ~
tar -xzf /tmp/tarballs/hwloc-2.9.3.tar.gz
cd hwloc-2.9.3
./configure --prefix=/apps/software/$USER/hwloc/2.9.3
make -j2
make install
/apps/software/$USER/hwloc/2.9.3/bin/lstopo --version
lstopo 2.9.3
# Output starts with "lstopo" — not "hwloc"

--prefix is not optional. Without it the default is /usr/local/bin — node-local, invisible to compute nodes. Everything in this lab installs to /apps/software/$USER/ via the shared filesystem.

1.2

Install likwid 5.3.0 — five edits to config.mk required

likwid's config.mk must be edited before building. Five edits. The defaults use ?= (conditional assignment) and comment out hwloc variables with #. The sed patterns must match exactly.

Commands — all five edits, in order
cd ~
tar -xzf /tmp/tarballs/likwid-5.3.0.tar.gz
cd likwid-5.3.0
# 1. PREFIX — uses ?= not =
sed -i "s|^PREFIX ?= /usr/local|PREFIX = /apps/software/$USER/likwid/5.3.0|" config.mk
# 2-4. HWLOC lines are commented out — uncomment AND set path
sed -i "s|^#HWLOC_INCLUDE_DIR = .*|HWLOC_INCLUDE_DIR = /apps/software/$USER/hwloc/2.9.3/include|" config.mk
sed -i "s|^#HWLOC_LIB_DIR = .*|HWLOC_LIB_DIR = /apps/software/$USER/hwloc/2.9.3/lib|" config.mk
sed -i "s|^#HWLOC_LIB_NAME = .*|HWLOC_LIB_NAME = hwloc|" config.mk
# 5. ACCESSMODE — accessdaemon causes chown root failure during install
sed -i "s|^ACCESSMODE = accessdaemon|ACCESSMODE = perf_event|" config.mk
make -j2
make install
/apps/software/$USER/likwid/5.3.0/bin/likwid-topology --version 2>&1 | head -1
likwid-topology -- Version 5.3.0 (commit: ...)

Why five edits, not three. PREFIX ?= uses conditional assignment — a plain PREFIX = pattern does not match it. HWLOC_INCLUDE_DIR, HWLOC_LIB_DIR, and HWLOC_LIB_NAME are all commented out by default — without uncommenting them likwid ignores your hwloc install and falls back to its internal copy. ACCESSMODE = accessdaemon causes make install to attempt chown root on the daemon binary — fails as non-root. perf_event skips this entirely.

1.3

Submit a SLURM job with manual PATH exports

The software is installed. To use it on the compute node you must manually export PATH and LD_LIBRARY_PATH in the job script. Use -v — see the notice below.

Write and submit job script
cat > ~/stage1.sh << EOF
#!/bin/bash
#SBATCH --job-name=stage1-$USER
#SBATCH --ntasks=1
#SBATCH --output=/home/$USER/stage1_out_%j.txt
#SBATCH --error=/home/$USER/stage1_err_%j.txt

source /apps/env.sh

# Stage 1 — manual environment wiring
# PATH finds the binary. LD_LIBRARY_PATH finds what it needs to run.
export PATH=/apps/software/$USER/likwid/5.3.0/bin:/apps/software/$USER/hwloc/2.9.3/bin:\$PATH
export LD_LIBRARY_PATH=/apps/software/$USER/hwloc/2.9.3/lib:/apps/software/$USER/likwid/5.3.0/lib:\${LD_LIBRARY_PATH:-}

# NOTE: tarball likwid 5.3.0 has a SIGFPE bug on this CPU — use -v
likwid-topology -v
EOF
sbatch ~/stage1.sh
watch squeue -u $USER
# Ctrl+C when job disappears from queue
cat ~/stage1_out_*.txt
likwid-topology -- Version 5.3.0 (commit: ...)

Why -v and not full topology. likwid 5.3.0 built from upstream source on Amazon Linux 2 + Skylake-SP CPUs has a SIGFPE (floating point exception) in its topology detection code. Bare likwid-topology crashes before printing anything. -v prints the version banner and exits cleanly — proving the binary was found on the compute node and its libraries loaded correctly. The bug lives in the upstream source you compiled. You absorbed it because you built from source. Watch what Spack and the container do differently in Stages 3 and 5.

2.1

Write the hwloc modulefile

Create /apps/modulefiles/$USER/hwloc/2.9.3.lua
mkdir -p /apps/modulefiles/$USER/hwloc
cat > /apps/modulefiles/$USER/hwloc/2.9.3.lua << 'EOF'
whatis("Name:        hwloc")
whatis("Version:     2.9.3")
whatis("Description: Hardware locality — topology detection and binding")
local root = "/apps/software/" .. os.getenv("USER") .. "/hwloc/2.9.3"
prepend_path("PATH",            root .. "/bin")
prepend_path("LD_LIBRARY_PATH", root .. "/lib")
prepend_path("MANPATH",         root .. "/share/man")
EOF

prepend_path not setenv. setenv("PATH", ...) replaces PATH entirely — the shell loses all system binaries. prepend_path adds to the front and preserves everything else. Most common modulefile mistake.

2.2

Write the likwid modulefile with depends_on

Create /apps/modulefiles/$USER/likwid/5.3.0.lua
mkdir -p /apps/modulefiles/$USER/likwid
cat > /apps/modulefiles/$USER/likwid/5.3.0.lua << 'EOF'
whatis("Name:        likwid")
whatis("Version:     5.3.0")
whatis("Description: Performance tools for x86 multicore")
depends_on("hwloc/2.9.3")
local root = "/apps/software/" .. os.getenv("USER") .. "/likwid/5.3.0"
prepend_path("PATH",            root .. "/bin")
prepend_path("LD_LIBRARY_PATH", root .. "/lib")
EOF
2.3

Rebuild the spider cache in your home directory

The spider cache must go in your own $HOME/.lmod_cache — not a shared path. update_lmod_system_cache_files calls chmod internally. chmod requires you to own the file. If another user wrote to a shared cache directory first your rebuild will fail with chmod: Operation not permitted.

Set MODULEPATH and rebuild — cache goes in $HOME
export MODULEPATH=/apps/modulefiles/$USER:${MODULEPATH:-}
# Cache goes in YOUR home — not /apps/lmod/cache (shared = broken)
mkdir -p $HOME/.lmod_cache
/apps/lmod/lmod/lmod/libexec/update_lmod_system_cache_files \
  -d $HOME/.lmod_cache \
  -t $HOME/.lmod_cache/timestamp \
  /apps/modulefiles/$USER
module avail
# Shows hwloc/2.9.3 and likwid/5.3.0
module spider hwloc
# Confirms cache was rebuilt

The Lmod binary path has three components named "lmod" — this is correct.
/apps/lmod/lmod/lmod/libexec/update_lmod_system_cache_files

Why: --prefix=/apps/lmod creates /apps/lmod/lmod/8.7/ with a version-agnostic symlink /apps/lmod/lmod/lmod → 8.7. The binary lives at the third level. Both lmod itself and update_lmod_system_cache_files live at /apps/lmod/lmod/lmod/libexec/.

module avail scans the filesystem — immediate. module spider reads the pre-built cache — stale until rebuilt. Always rebuild after adding or removing modulefiles.

Verify likwid-topology runs inside the container

Interactive test — three binds required

  --bind /tmp:/tmp \
  --bind /etc/passwd:/etc/passwd:ro \

Machine (2 packages):

# Full topology — AlmaLinux 8 glibc 2.28, no SIGFPE

Why /etc/passwd and /etc/group are required. Apptainer/Singularity checks your running UID against the container's /etc/passwd BEFORE entering. The AlmaLinux 8 base image has no entry for UIDs 2014–2019. Without these binds you get: FATAL: Couldn't determine user account information: user: unknown userid 2019. Binding the host's passwd and group files is the standard pattern on all shared HPC clusters running containers. The container sees your identity — all operations inside run as you.

common issues and fixes

Stage 1/2: Floating point exception when running likwid-topology with no flags.
Known SIGFPE bug in tarball likwid 5.3.0 on Amazon Linux 2 + Skylake-SP. Use likwid-topology -v — prints the version banner and exits cleanly. Full topology available via Spack module (Stage 3) and container (Stage 5).

Stage 1: likwid-topology: command not found in SLURM job.
Add the export lines inside the job script — not just your terminal session.

Stage 1: libhwloc.so.15: cannot open shared object file
LD_LIBRARY_PATH missing in job script. Export /apps/software/$USER/hwloc/2.9.3/lib inside the job.

Stage 1: make install fails — permission denied on daemon binary.
ACCESSMODE edit was missed. Check: grep ACCESSMODE config.mk — if accessdaemon, re-run:
sed -i "s|^ACCESSMODE = accessdaemon|ACCESSMODE = perf_event|" config.mk

Stage 2: SLURM job fails but interactive works.
MODULEPATH not set in job environment. Add export MODULEPATH=/apps/modulefiles/$USER:${MODULEPATH:-} before the module load line.

Stage 2: module spider does not show the new modulefile.
Spider cache stale. Run:
mkdir -p $HOME/.lmod_cache
/apps/lmod/lmod/lmod/libexec/update_lmod_system_cache_files -d $HOME/.lmod_cache -t $HOME/.lmod_cache/timestamp /apps/modulefiles/$USER

Stage 2: chmod: Operation not permitted while rebuilding spider cache.
You pointed at a shared cache directory that another user already wrote to. update_lmod_system_cache_files calls chmod internally — chmod requires you to own the file. Always use your own $HOME/.lmod_cache, never /apps/lmod/cache.

Stage 2: module list shows only likwid — not hwloc.
depends_on("hwloc/2.9.3") is missing from the likwid modulefile. Add it and reload.
