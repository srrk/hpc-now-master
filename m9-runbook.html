the lab story

The lab runs likwid-topology -v in Stages 1 and 2, and likwid-topology (no flag) in Stages 3 and 5. This is not an inconsistency — it is the lesson.

Stage Method Command in job Output Why
1 — Tarball Manual PATH exports likwid-topology -v version banner SIGFPE bug in 5.3.0 on AL2 — tarball inherits it
2 — Lmod module load likwid-topology -v version banner Same binary, same bug — Lmod fixed the environment, not the software

Spack and containers absorb that pain by choosing different versions or providing different runtimes. You will see this play out live across five stages.

Item 43 — Install to /apps
1.1

Install hwloc 2.9.3 from tarball

hwloc is the dependency. likwid links against it at compile time. Install hwloc first, into your personal /apps/software/$USER/ subtree.

Commands
cd /tmp/tarballs
tar -xzf hwloc-2.9.3.tar.gz
cd hwloc-2.9.3
./configure --prefix=/apps/software/$USER/hwloc/2.9.3
make -j2
make install
# Verify
/apps/software/$USER/hwloc/2.9.3/bin/lstopo --version
lstopo 2.9.3
# Note: output starts with "lstopo" — not "hwloc"

--prefix is not optional. Without it the default is /usr/local/bin — node-local, invisible to compute nodes. Everything in this lab installs to /apps/software/$USER/ via NFS.

1.2

Install likwid 5.3.0 — five edits to config.mk

likwid's config.mk must be edited before building. Five edits are required. The defaults use ?= (conditional assignment) and comment out hwloc variables with #. The sed patterns must match exactly.

Commands — all five edits required
cd /tmp/tarballs
tar -xzf likwid-5.3.0.tar.gz
cd likwid-5.3.0
sed -i "s|^PREFIX ?= /usr/local|PREFIX = /apps/software/$USER/likwid/5.3.0|" config.mk
sed -i "s|^#HWLOC_INCLUDE_DIR = .*|HWLOC_INCLUDE_DIR = /apps/software/$USER/hwloc/2.9.3/include|" config.mk
sed -i "s|^#HWLOC_LIB_DIR = .*|HWLOC_LIB_DIR = /apps/software/$USER/hwloc/2.9.3/lib|" config.mk
sed -i "s|^#HWLOC_LIB_NAME = .*|HWLOC_LIB_NAME = hwloc|" config.mk
sed -i "s|^ACCESSMODE = accessdaemon|ACCESSMODE = perf_event|" config.mk
make -j2
make install
/apps/software/$USER/likwid/5.3.0/bin/likwid-topology -v 2>&1 | head -2
likwid-topology -- Version 5.3.0 ...

Why five edits, not three. PREFIX ?= uses conditional assignment — PREFIX = does not match it. HWLOC_INCLUDE_DIR and HWLOC_LIB_DIR are commented out by default — the ^# prefix uncomments them. HWLOC_LIB_NAME — without it likwid ignores your hwloc path. ACCESSMODE = accessdaemon causes make install to try chown root on the daemon binary — fails as non-root. perf_event skips this entirely.

1.3

Submit a SLURM job with manual PATH exports

The software is installed. To use it in a SLURM job you must manually export PATH and LD_LIBRARY_PATH. Note: use -v not bare likwid-topology — see the notice below.

Write and submit job script
cat > ~/stage1.sh << EOF
#!/bin/bash
#SBATCH --job-name=stage1-$USER
#SBATCH --ntasks=1
#SBATCH --output=/home/$USER/stage1_out_%j.txt
#SBATCH --error=/home/$USER/stage1_err_%j.txt

source /apps/env.sh

# Stage 1 — manual environment wiring
# PATH finds the binary. LD_LIBRARY_PATH finds what it needs to run.
export PATH=/apps/software/$USER/likwid/5.3.0/bin:/apps/software/$USER/hwloc/2.9.3/bin:\$PATH
export LD_LIBRARY_PATH=/apps/software/$USER/hwloc/2.9.3/lib:/apps/software/$USER/likwid/5.3.0/lib:\${LD_LIBRARY_PATH:-}

likwid-topology -v
EOF
sbatch ~/stage1.sh
watch squeue -u $USER
# Ctrl+C when job disappears
cat ~/stage1_out_*.txt
likwid-topology -- Version 5.3.0 (commit: ...)
Built with HWLOC support ...

Why -v and not full topology. likwid 5.3.0 has a SIGFPE (floating point exception) in its topology detection code on Amazon Linux 2 + Skylake-SP CPUs. Bare likwid-topology crashes before printing anything. -v prints the version banner and exits cleanly — proving the binary was found, PATH was correct, and LD_LIBRARY_PATH was correct. The bug lives in the upstream source you compiled. You absorbed it because you built from source. Watch what Spack and the container do differently in Stages 3 and 5.

Item 42 — module avail, module show, module spider Item 43 — Write modulefile, verify on compute node
2.1

Write the hwloc modulefile

Create /apps/modulefiles/$USER/hwloc/2.9.3.lua
mkdir -p /apps/modulefiles/$USER/hwloc
cat > /apps/modulefiles/$USER/hwloc/2.9.3.lua << 'EOF'
whatis("Name:        hwloc")
whatis("Version:     2.9.3")
whatis("Description: Hardware locality — topology detection and binding")

local root = "/apps/software/" .. os.getenv("USER") .. "/hwloc/2.9.3"

prepend_path("PATH",            root .. "/bin")
prepend_path("LD_LIBRARY_PATH", root .. "/lib")
prepend_path("MANPATH",         root .. "/share/man")
EOF

prepend_path not setenv. setenv("PATH", ...) replaces PATH entirely — the shell loses all system binaries. prepend_path adds to the front and preserves everything else. Most common modulefile authoring mistake.

2.2

Write the likwid modulefile with depends_on

Create /apps/modulefiles/$USER/likwid/5.3.0.lua
mkdir -p /apps/modulefiles/$USER/likwid
cat > /apps/modulefiles/$USER/likwid/5.3.0.lua << 'EOF'
whatis("Name:        likwid")
whatis("Version:     5.3.0")
whatis("Description: Performance tools for x86 multicore")

depends_on("hwloc/2.9.3")
-- Lmod loads hwloc automatically. The researcher never types it.

local root = "/apps/software/" .. os.getenv("USER") .. "/likwid/5.3.0"

prepend_path("PATH",            root .. "/bin")
prepend_path("LD_LIBRARY_PATH", root .. "/lib")
EOF

Rebuild the spider cache

Set MODULEPATH and rebuild cache

Verify likwid-topology runs inside the container

Interactive test — both bind flags required

  --bind /tmp:/tmp \

Why /etc/passwd and /etc/group bind mounts are required. Apptainer checks your running UID against the container's /etc/passwd before the container starts. The AlmaLinux 8 base image has no entry for UIDs 2014–2019. Without these binds, Apptainer rejects the launch with: FATAL: Couldn't determine user account information: user: unknown userid NNNN. Binding the host's passwd and group files is the standard pattern on all shared HPC clusters running containers.

common issues and fixes

Stage 1/2: Floating point exception when running likwid-topology with no flags.
Known SIGFPE bug in likwid 5.3.0 topology detection on Amazon Linux 2 + Skylake-SP. Use likwid-topology -v instead — prints the version banner and exits cleanly, proving the binary works. Full topology is available in Stage 3 (Spack chose 5.2.2) and Stage 5 (container uses AlmaLinux 8 glibc).

Stage 1: likwid-topology: command not found in SLURM job.
PATH was set in your interactive session but not exported in the job script. Add the export lines inside the job script — not just your terminal.

Stage 1: libhwloc.so.15: cannot open shared object file
LD_LIBRARY_PATH is missing in the job script. Export /apps/software/$USER/hwloc/2.9.3/lib inside the job.

Stage 1: make install fails — permission denied on daemon binary.
The ACCESSMODE sed edit was missed. Check: grep ACCESSMODE config.mk — if accessdaemon, re-run: sed -i "s|^ACCESSMODE = accessdaemon|ACCESSMODE = perf_event|" config.mk

Stage 2: SLURM job fails but interactive works.
MODULEPATH not set in the job environment. Add export MODULEPATH=/apps/modulefiles/$USER:${MODULEPATH:-} before the module load line in the job script.

Stage 2: module spider does not show the new modulefile.
Spider cache stale. Run: /apps/lmod/lmod/lmod/libexec/update_lmod_system_cache_files -d /apps/lmod/cache -t /apps/lmod/cache/timestamp /apps/modulefiles/$USER

Stage 2: module list shows only likwid — not hwloc.
depends_on("hwloc/2.9.3") is missing from the likwid modulefile. Add it and reload.

Stage 3: variant error on spack install.
You wrote spack install likwid@5.2.2 -j2 — Spack reads -j2 as a variant. Use: spack install -j 2 likwid@5.2.2 (flag before the spec).

Stage 3: Cannot satisfy 'likwid@5.3.0'.
Spack 0.21.2 does not have likwid 5.3.0. Use likwid@5.2.2 for all Spack commands.

Stage 5: FATAL: Couldn't determine user account information: unknown userid NNNN.
The container's /etc/passwd has no entry for your UID. Add both bind flags: --bind /etc/passwd:/etc/passwd:ro --bind /etc/group:/etc/group:ro. This is standard practice on all shared HPC clusters running containers.

Stage 5: singularity: command not found.
Try: command -v singularity || command -v apptainer

Any learner Spack cache hit treated as an error
When Stage 3 — learner sees "already installed" and thinks the install failed
Spring "Spack said it's already installed. Is that a problem? Run spack find likwid — is it there? Run module avail likwid — can you load it? bootstrap.sh pre-built this before you logged in. This is the feature."
Any learner Stage 5 container rejects UID with FATAL error
When Stage 5 — singularity exec fails with FATAL: unknown userid NNNN
Spring "Read the FATAL message. Apptainer checks your UID against the container's /etc/passwd before the container starts. Your UID is not in the AlmaLinux 8 base image. What do you bind from the host to fix it?"
After Add --bind /etc/passwd:/etc/passwd:ro --bind /etc/group:/etc/group:ro to the singularity exec command. This is standard on every shared HPC cluster running containers. The container sees your identity — all operations inside run as you.
