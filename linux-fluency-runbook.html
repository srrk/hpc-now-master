how to use this runbook

This runbook runs alongside the Linux Fluency slide decks. Each section corresponds to a lab card shown during the session. When Rajesh shows a lab card on screen, open the matching section here.

Every command in this runbook is copy-pasteable. Do not type commands from the video screen — copy them from here.

After each command, compare your output to the Expected Output block. If your output does not match, read the If Something Goes Wrong block before asking for help. When you complete a section's checkpoint, type done in the session chat and wait for Rajesh to confirm the group is ready before moving on.

Ex 3

Confirm the current directory is not in PATH

echo '#!/bin/bash' > testscript.sh
echo 'echo "script ran"' >> testscript.sh
chmod +x testscript.sh
testscript.sh
Expected output
bash: testscript.sh: command not found

Expected output
script ran

The file exists. The shell cannot find it by name alone because the current directory is deliberately not in PATH.

~/bin now appears first — the shell searches it before anything else.

Ex 1

Create a directory structure

mkdir -p project/{src,config,logs}
ls -la project/

Your username appears as owner and group. First character d — directory.

Ex 2

Create files of different types

Set numeric permissions

ls -la project/config/

Ex 4

Verify that 0400 prevents accidental overwrite

Expected output

echo "recovered" > project/config/secret.conf

Expected output
recovered
Ex 5

Set setgid on a shared directory

mkdir project/shared
chmod 2755 project/shared
ls -la project/ | grep shared
touch project/shared/teamfile.txt
ls -la project/shared/

The s in the group execute position confirms setgid is set.

Ex 6

Set sticky bit

mkdir project/scratch
chmod 1777 project/scratch
ls -la project/ | grep scratch
Expected output
drwxrwxrwt 2 chandra chandra 6 Apr 25 10:06 scratch

The t in the other execute position — same mechanism as /tmp.

Ex 7

Hard link vs symbolic link behaviour

echo "original content" > project/src/original.txt
ln project/src/original.txt project/src/hardlink.txt
ln -s project/src/original.txt project/src/symlink.txt
ls -la project/src/

Link count of 2 on both — they share the same inode.

rm project/src/original.txt
cat project/src/hardlink.txt
cat project/src/symlink.txt
Expected output
original content
cat: project/src/symlink.txt: No such file or directory

Hard link survives. Symlink is now dangling.

Ex 8

Read an ACL

getfacl project/shared/

No + at the end of the permission string in ls -la means no extended ACL entries — only the base owner/group/other model.

The kernel boundary is hardware-enforced.
PID 1 is systemd on modern Linux systems.
The FHS defines where files live predictably.

/proc contains no files on any disk.

Symbolic links can point to things that do not exist.
