Session III · Linux Memory and Storage Internals
Observing Kernel State and Measuring Real Storage Throughput
This session establishes the operational difference between memory-backed I/O and real storage performance using live kernel observability.

Every Linux HPC administrator eventually encounters impossible benchmark numbers: 10 GB/s writes on storage capable of only 4 GB/s.

This session explains why that happens and how to prove the real behavior using only native Linux interfaces.

Central operational rule.

If a benchmark exceeds hardware capability, you measured cache — not storage.
exercise 1

Verify that /proc is a virtual filesystem

Kernel virtual filesystem
mount | grep '/proc'

ls -l /proc/meminfo

cat /proc/meminfo | head
Expected interpretation
/proc is generated dynamically by the kernel.
Files report zero size because they are not disk-backed.
Content is synthesized when read.
exercise 2

Read important fields from /proc/meminfo

grep -E 'MemFree|MemAvailable|Cached|Dirty|Writeback' /proc/meminfo
Field meanings
MemFree:
Completely unused RAM.

MemAvailable:
RAM available for new allocations.

Cached:
Filesystem data stored in RAM.

Dirty:
Modified pages waiting to flush.

Writeback:
Pages actively flushing to storage.
exercise 3

Compare MemFree and MemAvailable

free -h

grep -E 'MemFree|MemAvailable|Cached' /proc/meminfo
Interpretation.

Linux intentionally fills RAM with reclaimable cache. Low MemFree alone does not indicate memory exhaustion.
exercise 4

Inspect a live process using /proc/<pid>

Create a process
sleep 300 &
P=$!
Inspect process status
cat /proc/$P/status
Fields to identify
State
VmRSS
VmSize
VmHWM
Threads
exercise 5

Inspect fd, environ, cmdline, and maps

tr '\0' ' ' < /proc/$P/cmdline

tr '\0' '\n' < /proc/$P/environ | head

ls -l /proc/$P/fd

head /proc/$P/maps
The kernel's view of a process is authoritative. /proc exposes command line, environment, file descriptors, and virtual memory layout directly from kernel state.
exercise 6

Observe a D-state process

ps aux | grep ' D '

cat /proc/<pid>/status | grep State
Expected output
State: D (disk sleep)
D-state means the process is blocked inside kernel I/O and cannot be interrupted until the operation completes.
exercise 7

Diagnose blocked processes with stack and wchan

cat /proc/<pid>/wchan

sudo cat /proc/<pid>/stack
The kernel stack identifies the exact subsystem: NFS, Lustre, local disk, block layer, RPC, or filesystem code paths.
exercise 8

Run a buffered write benchmark

Observe cache before write
grep -E 'Cached|Dirty|Writeback' /proc/meminfo
Buffered write
dd if=/dev/zero of=io_test bs=1M count=20480
Buffered writes enter page cache first. The reported throughput primarily measures RAM speed.
exercise 9

Watch cache activity live

Terminal 1
watch -n 1 'grep -E "Cached|Dirty|Writeback" /proc/meminfo'
Terminal 2
dd if=/dev/zero of=io_test bs=1M count=20480
Observe the transition
Dirty rises first.
Writeback rises while flushing.
Cached remains high after write completion.
exercise 10

Run Direct I/O with O_DIRECT

dd if=/dev/zero of=io_test_direct bs=1M count=20480 oflag=direct

dd if=io_test_direct of=/dev/null bs=1M iflag=direct
O_DIRECT bypasses the kernel page cache and more closely measures actual storage throughput.
exercise 11

Drop caches correctly

sync

echo 3 | sudo tee /proc/sys/vm/drop_caches

grep -E 'Cached|Dirty|Writeback' /proc/meminfo
drop_caches is a debugging and benchmarking tool — not a fix for memory pressure.
